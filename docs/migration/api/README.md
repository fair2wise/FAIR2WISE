## 2. Shared service contract (`F2WOperations`)

Every method takes the server-resolved `RequestContext` first and forwards to the T10 services. The routes add HTTP validation, context resolution and response projection only.

**Projection (AUD-06).** Every `/v1` response body and every `job_event` SSE payload passes through the app's one `DisclosureProjector`, via `project_api_response` (`app/api/routes_common.project`): private keys (snippets, prompts, source text, crops, local paths, secrets) are dropped, `file:` URIs and served-artifact paths are dropped, absolute paths become opaque `f2w://` ids, secrets are redacted and every string is clipped to 600 characters (the B10 bound; the curation excerpt is cut to `EVIDENCE_EXCERPT_CHARS` first). Loopback Tiled targets, `sha256:` artifact refs, full event lists and the `corpus-audit` section names are kept. No `/v1` route has a turn's retrieved regions, so no verbatim quote is ever confirmed on `/v1`; the clip is the bound. `tests/api_v1/test_v1_disclosure.py` plants a canary in each store and asserts it never leaves.

**Error bodies.** A `ContractError` becomes `{code, message, retryable}` (plus `reason` when the site set one) at the status `app/api/auth.py::_STATUS` maps for the code (`conflict` is 409). `retryable` is the raise site's statement, not a property of the status: `unavailable` is retryable unless the site says otherwise (and carries `Retry-After: 5`); `conflict` is **not** retryable unless the site passes `retryable=True` (owner decision 2026-11-09, `reviews/H5/conflict_retryability.md`), which only a transient conflict does (a busy lock, a lease another run holds, a read that raced a writer). A job that hits a non-retryable `conflict` ends `failed` on its first run; a retryable one is requeued with backoff up to `MAX_CONFLICT_REQUEUES` times. Clients should treat `retryable: false` as terminal.

### 2.0.0 Library catalog, upload and verify (A8/T35, `:local` only)

`F2W_LIBRARY_DIR` (trusted startup setting; `/var/lib/fair2wise/library` in `docker/profiles/local.json`, an *optional* mount: absent means `mounted=false`; forbidden on the ALS profiles) names the papers folder. `LibraryService` (`app/modules/library/service.py`) reuses `FolderRoots` (label `library`) for root resolution, containment and the recursive PDF inventory; the T32 routes are untouched and there is no second listing route. State: `<F2W_WORKDIR>/library/catalog.sqlite` (sha256, local title and DOI, verification cache keyed by sha256) and `openalex_cache.sqlite`; the papers folder only ever receives uploaded PDFs. User PDFs are parsed by pypdfium2 in a child process (`app/modules/library/probe.py`: wall-clock timeout 20 s, CPU and memory limits on Linux, minimal environment). Local metadata never touches the network (socket-blocking test); only Verify does, and only with `OPENALEX_API_KEY` in the startup environment (otherwise `verify_status=error`, detail names the setting). Routes V56-V59 are in section 3; no route returns PDF bytes and none matches `SOURCE_SERVING_PATH_RE`. `index_status` reads `not_indexed` and `indexed_count` 0 until a `library_index` run (T36, below).

**T36 (library in the source index).** Submit `library_index` on `POST /v1/jobs` (no new route, no new policy row; rebuild with a new `params.nonce`). The job hashes the folder (no probe, no network), then chunks each new or changed PDF with `hybrid_rag.chunker.chunk_pdf_detailed` (`open_pdf` and page `get_text`; the PDF is parsed in the worker process, not the probe child) into the **literature index directory** `HYBRID_RAG_LITERATURE_INDEX` (`:local` profile: `/var/lib/fair2wise/state/session/source_index/literature` on the state volume; forbidden on `als-dev`/`als-prod`). Chunks have `corpus="library"`, `doc_id="lib:<relpath>"`, `work_id="doi:<doi>"` or `lib:<sha256[:16]>`, and a relative `path`; the existing `SourceIndex`/`PaperRetriever`/`HybridSourceRAG` path searches and cites them (`provenance.corpus="library"`). `meta.json["docs"]` maps each `doc_id` to `{sha256, n_chunks, title, doi, pages, status, chunker_version}` with `status` `ok` or `no_text` (scanned or unreadable PDF, `reason: "unreadable"` for the latter; reported, never a failure). Incremental: an unchanged paper (same sha256 and chunker version) is skipped and an unchanged library writes nothing; a changed paper is re-chunked, a removed one is pruned (only `library` chunks are touched). Work is one checkpointed `WorkUnit` per paper (`chunked_stage`: progress `units_done/units_total` plus `indexed`, `no_text`, `chunks`, `removed`, `unchanged`; cancel and resume), committed in batches of 8 and again on cancel or failure. Shared-directory safety (additive changes to `hybrid_rag/index_store.py`): `index_lock(root)` (flock on `.index.lock`) around every read-modify-write, `write_index` replaces `chunks.jsonl` then `meta.json` through temporary files and `os.replace`, `write_index(..., preserve_meta_keys=("docs",))` so `build_literature_index` (now locked, and keeping `library` chunks even on a full rebuild) no longer drops the `docs` record, and `SourceIndex` reloads when `meta.json` (mtime, size, inode) changes, so a long-lived reader follows rebuilds and never sees a torn file. Catalog: `papers.pages` (filled by the probe or the index run, migrated onto T35 catalogs) feeds `LibraryService.paper_facts(...).pages` for the T38 estimate; `papers.indexed_sha256` makes `index_status` one of `indexed`, `no_text`, `not_indexed`, `stale` (bytes changed since indexing); `GET /v1/library` `indexed_count` counts papers indexed with text for their current bytes; the paper DTO gains `pages`.

### 2.0.1 KG bundles, schemas, models and estimate (A8/T38, `:local` only)

Harvester (T45, `app/modules/library/harvest.py`, `app/api/routes_library_harvest.py`, policies V76-V79, V87, V88, `:local` only): `POST /v1/jobs` with kind `library_harvest` (capability `library.harvest`) and `inputs.params` `{topic (1-200 chars), category (library folder name, created on first filing), schema (registry id, label only), sources (subset of arxiv, openalex; default both), max_downloads (1-200, default 20), per_query (1-100, default 50), nonce}`. arXiv needs no key; OpenAlex needs `OPENALEX_API_KEY` in the worker environment (a source that cannot run is logged and skipped; the job fails only when no source ran). Tier A/B hits with an open-access PDF are downloaded (every redirect hop checked by `NetworkPolicy`, `%PDF-` check, size cap) and filed like an upload, with the registry's year, title and DOI; tier C is never downloaded; A/B hits without a free PDF become `paywalled`; open-access fetches the network policy refuses become `blocked` (host named) and other open-access fetch failures `failed`. The three statuses `paywalled`, `blocked` and `failed` (`MANUAL_STATUSES`) still need a PDF by hand. Results: `GET /v1/library/harvest/runs`, `GET .../runs/{run_id}/candidates`; such a candidate is completed with `POST .../candidates/{id}/pdf` (multipart `file`, one file per request; manual PDF flow, `mkdocs/docs/design-manual-pdf-flow.md`), `POST .../runs/{run_id}/pdf` (the batch drop, same body), `POST .../candidates/{id}/undo` or `POST .../candidates/{id}/dismiss`. A supplied PDF is validated like any upload (size cap 413, `%PDF-` 415, name), probed with the library's bounded probe and matched to the candidate (`app/modules/library/pdf_match.py`: DOI in the PDF, else title; verdicts `strong`, `weak`, `mismatch`). Only a strong match is filed without a click; weak and mismatch store nothing until the request is repeated with `confirm=true`. The filing records `provenance` (`user_supplied`, `user_supplied_confirmed`, `user_supplied_mismatch_confirmed`) and `supplied_by` (the acting principal's subject; the operator subject on `:local`) on the candidate and on the category manifest row. The server never fetches a paywalled paper and never sees the user's credentials or cookies. Text-mining rights for subscription content are the operator's responsibility to confirm.

Routes (policies V70-V75, `app/api/routes_library_kgs.py`, mounted by `create_api_app` on `:local` only; ALS answers 404): `GET /v1/library/kgs|schemas|models`, `POST /v1/library/estimate`, `POST /v1/library/kgs/continue`, `POST /v1/library/kgs/{name}/export`. Read routes and the estimate need `library.read`; continue and export need `library.extract`. Logic lives in `app/modules/library/{bundles,schemas,estimate,ranking,kg_service}.py`.

- **Bundle** `<F2W_WORKDIR>/kgs/<name>/{terms,kg,manifest,processed_pdfs,extraction_manifest}.json`. Names: `[A-Za-z0-9][A-Za-z0-9_-]{0,63}`; a collision is `409`; the directory is created with an atomic `mkdir`, the manifest is written last, a failed create is removed. Manifest: topic, `schema` (`id`, `version`, `sha256`, `path`), model, backend, papers (`name`, `sha256`, `pages`), `parent`, `reconstructed`.
- **Schema.** Choices are the v0.3.x entries of `SchemaRegistry` selectable for extraction (`matkg_schema@0.3.x`, `rsoxs_schema@0.3.x`; pending owner review, so chosen explicitly with `allow_pending_review=True`). The schema is locked per bundle: `fork` and `record_extraction` refuse a different one.
- **User schemas** (schema generation). `GET /schemas` also lists every stored user schema version after the registry sets: `origin: user`, `review_status: user_generated`, label `<title> (user schema, vN)`, id `user/<name>@vN`, `sha256`, no path. Any of them is accepted wherever a schema id is: estimate, `library_extract`, `kgs/continue` with a KG file, and the Harvester's `schema` label. A bundle locks it like a shipped schema (manifest `{id, version: "vN", sha256, path: "<name>/<name>@vN.yaml"}`, path relative to `<F2W_WORKDIR>/schemas`). `GET /kgs` summaries add `schema_origin` (`user` or `shipped`), `schema_name` and `schema_version`; the export metadata `schema_info` carries the same three fields.
- **Continue.** `POST /kgs/continue` takes `name` and exactly one of `parent` (a bundle; schema inherited, a different `schema` is refused) or `source` (a plain `*.json` in the release directory; `schema` required; reversed with `kg_to_terms` into a bundle with `reconstructed=true`).
- **Export.** `POST /kgs/{name}/export` with body `{"confirm": true}` writes `matkg_<name>.json` into the release directory (`F2W_KG_RELEASE_DIR`, default `storage/kg`) with `metadata.schema`; it never overwrites a file that is not this bundle's earlier export and never follows a link.
- **Models.** `GET /models` is the live `CachedModelCatalog` (shared with the judge-model setting) filtered by the free-model policy (owner decision 2026-11-09, `app/modules/model_policy.py`: only free LBL-hosted ids; a listed price above 0 excludes a model); the body adds `model_policy` (`source`, `as_of`, `default_model`, `free_models`). `available=false` without a backend. A `library_extract` job whose `params.model` the policy refuses fails at once with `denied` (`reason: model_not_free`) before the bundle lock or any client. No route here calls or changes `PUT /settings`.
- **Estimate.** pages x fixed per-page token heuristics (1200 in, 400 out); cost only for models with a configured price (none built in, so `estimated_cost_usd` is `null` by default). `confirmation` is the SHA-256 of the canonical selection (papers with sha256 and pages, model, schema, heuristics, price); `KgLibrary.check_confirmation` (for T39's start path) refuses a mismatch with `stale_approval`. `/v1/curation/cost-approvals` (V14) does not fit (human `curation.approve`, corpus scope, USD cap, expiry, bound to review cases), so the confirmation is local.
- **Paper lookup.** The estimate reads pages and sha256 through `app.state.f2w_library_papers` / `KgLibrary.papers` (`PaperLookup.paper_facts(id)`); until T35 installs it the estimate answers `503 unavailable`.
- **Legacy Settings model (free-model policy, 2026-11-09).** `GET`/`PUT /settings` keep their frozen shape; `available_cborg_models` holds only free LBL-hosted ids and a `model` the policy refuses is replaced by the default free model (the UI shows a notice). The runtime's active CBORG model is always a free id (`default_runtime_model`).
- **Legacy Settings list (additive hooks).** `list_storage_kg_json_files()` appends `kgs/<name>/matkg_<name>.json` for every bundle (read from `F2W_WORKDIR`); `_resolve_json_graph_path` first maps exactly that virtual path to the bundle's `kg.json`. `schema_path_for_graph` is unchanged; `bundles.schema_path_for_registered_graph` is the manifest-based lookup (not yet called by `retrieval_agent`).

- **T39 (`library_extract`).** Submit on `POST /v1/jobs` (capability `library.extract`, no route, no policy row; a new `params.nonce` is a new run). `params`: `bundle` (name), `papers` (library paper ids), `model`, `schema` (an offered v0.3.x id; locked per bundle), `topic`, optional `continue_from` (a bundle name: the new bundle is a fork of it), `confirmation` (the `/estimate` token), optional `backend` (`cborg` or `ollama`: the job's own choice over `F2W_EXTRACT_BACKEND`; `ollama` needs `OLLAMA_URL` set in the worker's environment, with no localhost default, and its model names are not subject to the free-CBORG-model policy). `GET /v1/library/models` also returns an `ollama` block (`state` ok/empty/unset/unreachable/error, `models`, `error`; never the URL) listed from `{OLLAMA_URL}/api/tags` independently of CBORG, and an `error_code` (`cborg_ip_not_authorized` when CBORG refuses this network address with HTTP 403). The model rides in the job inputs and never goes through `PUT /settings`. Order: validate inputs, **fail closed** with `unsupported_capability` unless a backend is configured in the worker's startup environment (`CBORG_API_KEY`, or `F2W_EXTRACT_BACKEND=ollama` with optional `OLLAMA_URL`; no dotenv, no client is built and nothing is contacted otherwise), `KgLibrary.check_confirmation` (`stale_approval` on a mismatch), the per-bundle `flock` (`<F2W_WORKDIR>/kgs/.locks/<name>.lock`; a second run gets a retryable `conflict`, a killed worker frees it), then create the bundle, fork `continue_from`, or reuse an existing bundle (schema locked). One checkpointed `WorkUnit` per PDF through `Orchestrator.process_pdf` (unit id = paper id; unit key = PDF sha256 + `EXTRACTOR_REVISION` + schema id and file hash + model), so a killed worker resumes without redoing finished PDFs, and a changed model, schema or file re-runs. A PDF the model run cannot read or that raises is a failed unit (`incomplete`, job ends `failed` with "retry resumes") while the others finish; cancel stops between PDFs and still writes importance, `terms.json`, `kg.json` and the manifest for what finished. A paper already extracted into the bundle with the same bytes and model is skipped. After the units: `assign_importance`, `TermStore.save`, `kg_update.rebuild_kg` (`kg.json`), `BundleStore.record_extraction` (`manifest.json`). `processed_pdfs.json` and `extraction_manifest.json` carry the entries `Coordinator._record_full_extraction` writes (keyed by file name, so two selected papers with one name are refused). Logs: the extractor's standard-library logs (`app.modules.term_extractor`, `f2w.output`) and the job's own lines are forwarded to the job log with T33 `capture_job_logs` (one capture per process; a second extraction in the worker gets a retryable `conflict`); progress counters are `units_done`, `units_total`, `units_reused`, `units_failed`, `extracted`, `pages`, `pages_with_terms`, `skipped`, `papers_in_bundle`. The API process registers the handler for validation and the worker (`app.modules.workers.factories:library_service`) runs it.

### 2.1 Job UI mapping (`GET /v1/jobs/{id}/view`)

`ui_state` is derived from the job state and, for publication jobs, the plan/approval/receipt/pointer records. Staged never reads as published.

| `ui_state` | Meaning |
| --- | --- |
| `queued`, `running`, `paused`, `failed`, `cancelled`, `completed` | Job lifecycle |
| `awaiting_review` | Non-publication job waiting for a person |
| `staged` | A publication plan waits for approval; nothing is written to the target |
| `approved` | A valid approval for the current plan is recorded; nothing imported yet |
| `published` | Receipted and the active pointer of the target |
| `superseded` | Receipted, but no longer the active pointer (later publication or rollback) |
| `quarantined` | A package, snapshot or step output was quarantined |

### 2.2 Job event stream (`GET /v1/jobs/{id}/stream`)

Legacy SSE framing (`event:`/`data:` LF blocks, as `/chat/stream`) with `JobEvent` payloads: `event: job_event` with `id: <sequence>` per durable event (reconnect with `Last-Event-ID` or `?after=`), then exactly one `event: end` with `{"state", "reason"}`, where reason is `terminal`, `waiting` (awaiting review or paused), `timeout` or `denied`. Additive (T33): `event: job_log` frames carry one log line each (`{seq, at, level, stage, message}`) with no `id:`, so `Last-Event-ID` still means job-event sequences; a fresh stream replays the kept lines, `?logs_after=<seq>` skips earlier ones, and clients that reconnect resume logs through `GET /v1/jobs/{id}/logs?after=`. The context is re-resolved before every poll, so a sign-out ends the stream.

## 3. Route policies (`app/api/policies.py`, DEP-19)

All 67 routes are declared with `RoutePolicy`; `app.api.auth.lookup_policy` resolves them for the legacy surface the factory extends, and `undeclared_routes` now also fails closed on routes it cannot inspect (mounts, lazily included routers). Rules:

- A route whose effect needs one fixed capability declares it, so the dependency refuses the caller first and, for an admin capability, re-runs the ALS role check.
- Routes whose capability depends on the job kind or on ownership declare no entry capability (signed-in on ALS) and rely on `JobService`; their mutating handlers re-run the ALS role check (`fresh_request_context`).
- A policy with `on_als=False` (V39-V41, the T32 folder routes) is registered by the factory on the `:local` profile only. An ALS profile has no such route, so it answers a plain 404 (`{"detail": "Not Found"}`) to everyone, signed in or not; the ALS image profiles also refuse the `F2W_FOLDER_ROOTS` setting (`forbidden_env`), and the factory ignores it with a warning if it is present anyway. The gateway (`docker/nginx.conf`) forwards every `/fair2wise/api/v1/...` path unchanged, so the 404 is the app's (`tests/gateway/test_gateway_prefix.py::test_t32_folder_routes_are_404_on_als_behind_the_gateway`).
- On `:local` the caller is the local operator with every capability (D34); no identity call is made. That includes `trace.read_any`, so `GET /traces/{turn_id}` returns the **raw** trace (full prompts with source page text) to every caller (owner decision 2026-10-12, AUD-16). This is fine for one trusted operator on loopback. Do not bind `:local` beyond loopback (`F2W_LOCAL_BIND=network`, or `--host` other than a loopback address) without accepting that everyone who can reach the address reads those traces; both `run_api` entry points log a WARNING when they do (`app.api.auth.warn_if_exposed`), and startup logs it when `F2W_LOCAL_BIND=network`. The policy itself is unchanged.

## 3.2 Publication pointer Model C: last activated plus a per-corpus live view (owner decision 2026-11-09)

The owner chose Model C of `reviews/H5/pointer_model_memo.md`. There is still **one pointer per target**, and it means
"last activated" (any corpus). No table was added: `PublishStore.live_by_corpus(target)` derives, from
`pub_pointer_history`, the live version of every corpus (each row's `snapshot_ref` is `<corpus>/<vN>`; the last
`activate` or `rollback` row naming a corpus wins; a `retire` row removes the corpus named by `corpus=<scope>` in its

## 3.1 Rollback, replacement and the two-pointer toggle (T10B, owner decisions B28, B27, Q14, Q15)

**Two pointers, one toggle (B28).** The publication pointer of a target keeps its history (`pub_pointer_history`).
`PublishStore.previous_record` names the pointer one step back; asking again after a rollback names the one that was
rolled back from, so rollback is a toggle between the **last two pointers**: a second rollback is a roll-forward.
History rows carry `action` (`activate` or `rollback`) and the reason; candidates, receipts and snapshots are never
deleted by a rollback. The code rollback (the image) stays independent of this data rollback (REL-08).

**Which rollback.** With the replacement importer (`jobs/replacement_step.ReplacementPublishStep`, the one that keeps a
release-marker entity in Tiled) a rollback is a **replacement plan whose source is the previous pointer's snapshot**
(`Publication.rollback_replacement`, V53). The importer revives the retired records whose content equals that
snapshot, so v5 to v4 to v5 restores the same Tiled UUIDs. The job plans, waits for the V18 approval, imports,
verifies, receipts and activates like any publication; the pointer moves with `action = rollback`. The pointer-only
`Publication.rollback` (V20) would leave the Tiled marker and the pointer disagreeing, so it answers 409 `conflict`
with `reason = "rollback_replacement_required"` and a message naming `rollback_replacement` (V53) on such a deployment,
and stays valid only for importers without a marker.

**Marker and pointer agree after every step (TIL-14).** Before the pointer is switched the activate stage reads the
live release marker from Tiled; if it does not name the snapshot and plan being activated the stage quarantines and
the previous pointer stays active. `Publication.verify_agreement(ctx, target, scope)` reports
`{agree, pointer_snapshot_id, marker_snapshot_id}` (both `None` after a corpus removal).

**One pointer per target, several corpora: a no-op rollback (T13 E2E rehearsal, 2026-11-06).** The pointer is per
*target*, the release marker and the scope revision are per *corpus*. Publishing corpus B after corpus A retires
nothing of A (different scope), so a rollback-replacement from B/vN back to A/vM plans **zero operations**
(`creates 0, links 0, supersessions 0`, `is_noop`): A's records are all still live and A's marker still names vM.
Such a rollback **moves the pointer and writes nothing to Tiled**; it never removes B, whose records, marker and
revision stay as they are (removing a corpus is `corpus_retire`, V54). The importer answers `noop` with the receipt
that put A/vM live (an older plan hash); `ReplacementPublishStep.apply` then writes a thin receipt of kind `noop`
under the rollback plan's own hash (zero counts, `outcomes.noop = 1`, the live records' identity mapping), so the
job's receipt stage (plan hash, approval, snapshot) and the pointer stay strict and unchanged. Verification of a
`noop` receipt requires, beyond its own target and revision, that the covering replacement receipt (same snapshot,
same scope, this adapter, not itself a noop) is valid for the scope revision read *now*
(`ReplacementPublishStep.covering_receipt`); the activate stage accepts the marker naming that covering plan and
receipt (and the snapshot's `graph_sha256`) in place of the rollback plan's hash, nothing else. The receipt-stage
report carries `noop: true` and `covered_by: <covering receipt id>`; job progress reports `created 0`. Before this
fix the job quarantined at `verify` ("no receipt matches the target as read back now") although Tiled was untouched.
A quarantine row (`pub_quarantine`) only annotates that job's view (`ui_state = quarantined`); it blocks no later
submission, approval or activation on the target. A rollback re-submitted with the *same* reason is the same job
(idempotent job identity: kind, snapshot, target, pointer version, reason) and stays failed, and `resume` does not
heal it either (the completed `import` stage is reused, so `verify` fails again): submit the rollback again with
another reason, which is a new job. *Owner decision 2026-11-09 (fourteenth set), "Auto-approve on :local only":* a
**zero-operation rollback plan is approved automatically on the `:local` profile only**. The publication job's
`review` stage offers a rollback job's plan to the deployment's `PublicationDeps.auto_approve` policy only when
`ReplacementPublishStep.plan_is_noop(plan)` holds (no creates, links or supersessions, no boundary links or legacy
adoption, the scope still at the plan's base revision, and a covering replacement receipt valid now). On `:local` the
policy (`post_extraction.noop_rollback_auto_approver`, wired by `build_local_publication`) makes the same
plan-hash-, job-, target- and profile-bound approval of the local operator that a person's approval is, verified by the
same `verify_approval`, stored with `record_approval`, and marked `reason = "auto_safe_plan"` (the T18E marker; a human
approval has `reason = null`), so the audit trail names it as a policy decision, never as a human one. On any other
profile the policy answers nothing and the job waits for the V18 approval; every non-empty plan, every non-rollback
publication, and a deployment without the policy (the default of `PublicationDeps`) still wait for the human route.

**Reviewed resolutions (Q15, T23C).** A rollback below a snapshot that carries a `reconciled` edit is refused at plan
time unless each such edit has a reviewed `ConflictResolution` (`discarded` or `carried`) passed as
`resolutions` on submit; the resolutions are bound into the plan hash.

**Foreign changes (Q14).** A record that FORGE or anyone else changes during a run never stops it; the importer's
receipt lists `foreign_changes` and the job's `receipt` stage returns them in `result.report.foreign_changes`.

**Stale approval (B27).** If the schema, vocabulary, snapshot or the scope's revision moved after planning, the runner
invalidates the approval and re-plans in the same run, then waits for approval of the new plan (a replacement plan
included: a changed owned row of the scope changes `base_revision`). A changed snapshot is quarantined, not re-planned.

**Legacy adoption** of per-version imports needs `jobs.admin` on submit (`adopt_legacy`) and an explicit approval; a
plan is *safe* (eligible for a `:local` auto-approval policy) only with no boundary links and no legacy adoption.
**Corpus removal and purge** are separate jobs (`corpus_retire`, `corpus_purge`; V54, V55) with their own plans and
approvals; a full purge after a removal needs `include_previous` as the second explicit choice.

**Job kinds (B5/J-11).** `enrichment`, `topic_sweep` and `pdf_parse` (`jobs/paper_jobs.py`, V50-V52) replace the donor
start/status/stop route triples: submit is the V50-V52 route, status `GET /v1/jobs/{id}`, stop `POST /v1/jobs/{id}/cancel`.
The kind capability is `jobs.admin` (verified admins on ALS); the work is a handler port bound by trusted wiring, so
the lifecycle, parameter validation, cancellation and resume are tested with fake handlers and no model or parser runs
in the API process. Anything a handler proposes for the graph still goes through the `curation.approve` review.
The real handlers (`jobs/paper_handlers.py`, T-handlers) port the donor enrichment agent over injected ports (catalog,
OpenAlex, corpus, acquisition, parser) and emit `graph_proposal` review cases only; what they do and what was
deliberately not ported is in `docs/migration/reviews/H8/handler_port_notes.md`.

## 5. Browser-origin protection and the sign-out CSRF decision (T25C follow-up 1)

**Decision.** `POST /auth/sign-in` and `POST /auth/sign-out` (in every app that mounts them, including the legacy `create_app`) and every state-changing `/v1/` and `/auth/` request in `create_api_app` are refused with 403 `cross_site_request` before any effect when:

1. `Sec-Fetch-Site: cross-site` is present, or
2. an `Origin` header is present and is neither the request's own host (`Host`, or the gateway's `X-Forwarded-Host`/`X-Forwarded-Proto`) nor in the allowlist (the app's CORS origins; for the sign-in handlers, an explicit `allowed_origins` argument, default none: ALS is same-origin under `/fair2wise`).

A request with neither header (curl, SDK, tests) passes: it is not a browser CSRF vector and still needs a valid session or the local profile.

**Why not a session-bound CSRF token now.** Access contract section 9 asks for a CSRF token bound to the server session on ALS. The frozen UI has no sign-in page and cannot send a token, and changing it is out of scope. The session cookie is already `SameSite=Strict`, which stops cross-site requests from carrying it; the origin check adds protection against same-*site* siblings (other `*.lbl.gov` hosts), login CSRF, and simple (non-preflighted) POSTs. A synchronizer token arrives with the gateway sign-in UI (T24C); the handlers are ready to add it.

**Legacy routes (T28A, AUD-04).** Since T28A `create_app` itself applies the same origin gate to every state-changing request on the 19 legacy UI routes, and caps request bodies at 128 MiB (`LEGACY_MAX_BODY_BYTES`, the gateway's `client_max_body_size`). Same-origin browsers, the Vite development origins on `:local`, configured `cors_origins`, and non-browser callers see no change in any response; only cross-site state-changing requests (403 `cross_site_request`) and oversized bodies (413 `payload_too_large`) are refused before any route runs. On `als-dev`/`als-prod` an empty `cors_origins` no longer falls back to the localhost development origins with credentials (C7): it means no cross-origin browser access.

**Sessions are in memory (T25C follow-up 2).** `TiledSessionStore` lives in one process; a restart signs everyone out. Left as is; a persistent or shared store is a T24 deployment item.

## 6. Scope change wiring

`AccessRuntime.on_scope_change` listeners receive `{"subject", "reason"}` when:

- an ALS caller signs out (`reason: signed_out`; the subject is resolved from the session before it is dropped), or
- a verified admin is seen without the admin role at a later check (`reason: role_downgraded`).

`create_api_app` registers `F2WOperations.notify_scope_change`, which calls `JobService.notify_scope_change`; `Publication` then invalidates every valid approval the subject requested or approved. Workers stop at their next boundary through `WorkerAuthority`. Signing out one browser session invalidates that subject's approvals everywhere (fail closed).
