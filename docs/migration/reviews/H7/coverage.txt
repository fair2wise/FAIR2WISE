ENVIRONMENT CAVEAT for the "before" column (important for the integrator)
  The full-suite log the "before" numbers came from (scratchpad full-suite-cov.log, 60 failed / 4963 passed) was
  produced in an environment where pypdfium2 could not be imported: tests/vision (25 failures), the literature
  parsing tests, tests/test_paper_evidence_agent.py (4), tests/api_wiring/test_wiring_quotes.py (8) and
  tests/evals_binary (20) all failed with "PdfUnavailable: pypdfium2 is not installed". Those failures are why
  vision/*, literature/parsers.py, literature/pdf_reader.py and f2w_agent/paper_evidence_agent.py read 33-53% there.
  In the interpreter used for this work (venv-app, pypdfium2 present) those existing tests pass and the modules
  already reach 83-98% with NO new tests: parsers 84.5, pdf_reader 98.5, vision scale/tables/qrange/figure_extraction/
  text_layer/ocr/tools 83-98, paper_evidence_agent 86.1. Only vision/kernels/panels.py (77.9 even with the vision tests)
  needed new tests (tests/coverage_t27/test_vision_panels_extra.py). If the integrator's full-suite run is again in an
  environment without pypdfium2, those modules will read low again for the same reason; fix the environment
  (pixi.toml already lists pypdfium2 = "*"), not the tests.

Application changes made while testing (also reported in the hand-off)
  agents/properties.py: the unit tests that lived inside the module (never collected by pytest, so never run)
      moved to tests/coverage_t27/test_agents_properties.py and `import pytest` was removed from production code.
      Run for the first time, three of them failed: "band gap of Na3Bi is 1.9 eV" produced a spurious entry
      raw_value "3", unit "Bi" (digits inside the material name), and every later number in the sentence
      ("300 K") became another entry. extract() now masks the material and property phrase before searching for
      a value and keeps the first value after them.
  tiled_graph.py: entity_to_node indexed props['proposal_code'] inside an f-string guarded by
      "proposal_code or proposal_id"; an entity with only proposal_id raised KeyError and aborted the whole
      identity lookup. Fixed with props.get().
